# Releaseforge One-Command Demo Design

## Goal

Give a new user a safe, local, one-command way to experience the complete
Releaseforge workflow immediately after installation, without adding real media
or a real release folder to the test.

## Command

```text
releaseforge demo DESTINATION
```

`DESTINATION` must not already exist. The command creates a synthetic demo only
inside that new directory. It never inspects, modifies, uploads, or copies a
user's release material.

## Output layout

```text
DESTINATION/
  START_HERE.md
  release-v1/
  release-v2/
  proof-v1/
  proof-v2/
```

Each `release-v*` folder contains a valid generated cover, a short generated
WAV file, and a complete `release.toml`. Each `proof-v*` folder is built via the
same public report path used for a real release. The second cover has different
bytes while the rest of the simulated release is unchanged, so the immediate
comparison has one clear verified-asset difference.

## Boundaries

- Everything generated by `demo` is synthetic and local only.
- The illustrative declarations are not evidence of rights, approval, or
  delivery readiness; the generated guide says this plainly.
- The command refuses an existing destination and does not overwrite it.
- The guide points to read-only `compare`; no automatic external handoff,
  publication, or account action is involved.

## Acceptance criteria

- A fresh destination contains the guide, two release folders, and two full
  proof packets.
- `compare proof-v1 proof-v2` returns a captured cover-byte change.
- Packet and comparison output contain no machine-specific source path.
- A pre-existing destination is untouched and produces a non-zero command
  result.
